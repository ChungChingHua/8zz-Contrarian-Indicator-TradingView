## 資金配置、成交與比較

所有事件明示原標的及「→0050.TW（全部代理）」，即使已辨識原標的，也不在此混用個股報酬。單一部位、每次帳戶淨值 100% 名目本金，不重疊、不實際加碼；結算後按淨值複利，持有中按最新同標的收盤估值。曲線逐筆核對，沒有把不同股票百分比相加。空單用等額名目本金，沒有模擬保證金追繳、借券可得性、借券費或融資條件，不能直接當成真實帳戶保證可成交的績效。

每筆成交使用嚴格晚於發文時刻的第一個已完成收盤。Yahoo 日線開盤戳加台灣 4.5 小時視為 13:30 收盤；半小時戳加 30 分鐘，收盤時間以 13:30 為上限。這是收盤成交近似：假設可在該收盤價成交，沒有建模下單延遲。固定 A 進場後再數 17 根；A 持倉中相反訊號不覆寫原 A 部位，不重疊進場。首根行情距訊號超過 7 日時列缺行情，避免把有限保留期外的事件延遲數月進場；此檢查不是訊號判讀條件。

0050 買入持有與策略從同一首筆進場價、同一估值期間開始，初值皆為 100。行情使用 Yahoo quote.close，不用調整收盤；本次期間的資料未另做公司行動稽核。未計股息、手續費、稅、滑價，不是總報酬指數。

清單篩選支援日期（台北時間）、平台、多空、強度、關鍵字。篩選只影響事件清單及篩選摘要，上方戰績與曲線保持全樣本，避免刪去中間翻轉後重算出不一致交易。

## 網站、README 與 Pine 參數

| 項目 | 本次採用 |
|---|---|
| 固定持有 | `holdBars=17`，網站 A 僅接受 30 分鐘；不把 17 日或 17 小時冒充 17 根半小時 |
| 訊號有效期 | `signalLifeBars=24`，只控制視覺有效性，不作強制平倉 |
| 濾網 | 原預設均關閉，不新增 EMA／RSI 等門檻 |
| Mode B | 反向方向出場；網站以日線收盤批次執行，Pine 依所選圖表 bars 執行 |
| 勝敗平 | 多空損失均計敗、零報酬列平、未平倉不算已結算 |

Pine 原本的 A 結算參照共用 flipBar，遇提前翻轉會遺失前 A 交易。已改獨立 A 持倉，只在到期且無 A 部位時接受新翻轉；B 仍依方向翻轉平倉。根目錄 Pine 保留原有事件集合，完整 187 事件仍在 candidates/8zz-history-latest.pine；兩者套用相同計帳修正，候選產生器也會套用。中性事件保留但不再當成交易。沒有改情緒標準或事件欄位。

Pine 仍依圖表標的／週期成交；同一圖表棒中可能順序處理多個事件，網站則合併同一成交收盤的淨方向。網站 B 日線不等於 Pine 30 分鐘，不能宣稱報酬數字相同。本次沒有 TradingView 實際編譯或 broker 回測。此前 PINE_INITIALIZATION_FIX.md 的「初始化以外逐字不變」僅描述先前初始化修復，本次另明示修改計帳層。

舊 scripts/build_site_data.py、docs/events.json 僅保留相容性，不是本看板的資料入口，其混合週期與多標的交易口徑不應用來引用新看板結果。

## 後續更新（不耗 AI 或 Apify）

只更新行情與重算：

```sh
python scripts/build_audited_dashboard.py --refresh-market
```

僅從已保存行情離線重建：

```sh
python scripts/build_audited_dashboard.py
```

此命令只讀候選 Pine、保存來源與判讀進度，行情更新僅存取 Yahoo 的既有 Jina 備援。沒有匯入或執行抓文／模型入口。讀取失敗會記錄 market.errors；缺行情不生成假價格，對應事件顯示缺資料。每次重建更新 dashboard-data.json、dashboard-data.js、preview.html，index.html 不需改動。

若另有合法取得的歷史 30 分鐘行情，可在 data/dashboard_market.json 的 series["30m"] 匯入 {"time": 已完成收盤的 UTC 毫秒, "price": 真實價格}，按時間排序，保留來源與取得時間後離線重建。不可把小時線／日線複製成半小時線。日線同理放在 series["1d"]。目前沒有持續排程，需手動執行；判讀額度恢復後是否接續仍另循原有授權流程，本命令不會啟動它。
